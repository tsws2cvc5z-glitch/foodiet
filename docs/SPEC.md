# Foodiet 仕様書（ヒアリング反映版 v0.2）

個人で使う体重管理アプリ。食事を記録し、ヘルスケアの消費カロリーと目標体重から「今日食べていい量」を出す。

## 1. 前提・構成

| 項目 | 決定内容 |
|---|---|
| 利用端末 | iPhone（Mac なし） |
| アプリ形式 | Web アプリ（PWA）。Safari で「ホーム画面に追加」して使う |
| サーバー | Cloudflare Pages ＋ Pages Functions（Workers）＋ D1（無料枠） |
| データ保存 | D1 に保存する（機種変更してもデータはそのまま） |
| アクセス制限 | Cloudflare Access（メール認証）で自分だけが使える。ショートカット用には専用トークンを発行する |
| ヘルスケア連携 | iOS「ショートカット」のオートメーションで、ヘルスケアの値をサーバーへ定期送信する |
| Garmin | Garmin Connect → Apple ヘルスケアの同期を使う（アプリは直接つながない） |
| 技術 | React ＋ TypeScript ＋ Vite、グラフは Recharts |

## 2. 初期設定（初回起動時）

- 性別、年齢、身長、現在の体重
- 目標体重、期限（日付）
- 入力すると、1日あたりの目標赤字と、目安の摂取カロリーを表示する
- 目標が厳しすぎる場合は警告する（例：減量ペースが週あたり体重の1%を超える）
- 設定画面からいつでも変更できる（今日のサマリー右上の歯車から開く）

## 3. 「今日食べていい量」の計算

```
基礎代謝   = Mifflin-St Jeor 式（性別・年齢・身長・最新の体重から計算）
1日の赤字  = (現在の体重 − 目標体重) × 7,200kcal ÷ 期限までの残り日数
借金の返済 = 借金残高 ÷ 期限までの残り日数
今日の枠   = 基礎代謝 + 今日のアクティブカロリー(実測) − 1日の赤字 − 借金の返済
```

- 朝は「基礎代謝ベース」の枠から始まり、運動するとアクティブカロリーの分だけ枠が増える
- 1日の赤字は体重を記録するたびに計算し直す（予定より進んでいれば赤字は小さくなる）
- 枠の下限を設ける（例：基礎代謝の80%）。下限にかかったときは目標の見直しを促す

### 借金（枠の超過分）

- 1日が終わった時点で `摂取 − 確定した枠` がプラスなら、その分を借金に加える
- 借金は目標期限までの残り日数で割り、毎日少しずつ枠から差し引いて返す
- サマリーに借金残高、通算記録に借金の推移を表示する
- 前日のアクティブカロリーが確定してから借金を確定させる（翌日に一度でも同期があるか、翌日の12時を過ぎた時点）
- 記録が1件もない日は借金を動かさない（返済もしない）

## 4. 画面構成（下部タブ3つ）

### ① 今日のサマリー
- 今日の枠のゲージ（摂取 ／ 枠、残り kcal）。超過したら色を変える
- 内訳：基礎代謝、アクティブ、赤字、借金の返済
- PFC（たんぱく質・脂質・炭水化物）のバー
- 朝・昼・晩・間食ごとの記録一覧（タップで編集）
- 今日の体重（未入力ならその場で入力できる）
- 借金残高、ヘルスケアの最終同期時刻

### ② 通算記録
- 摂取カロリーと消費カロリーのグラフ（日・週・月・年で切り替え）
- 体重の推移と、目標までの予定ライン
- PFC バランスの推移
- 借金の推移、超過した日数

### ③ 食事登録
- 区分（朝・昼・晩・間食）と食べた時刻
- 食品の探し方
  - 履歴・お気に入りから（よく食べるものが上に出る）
  - 日本食品標準成分表（八訂）を検索（約2,500品目、ひらがなでも検索できる）
  - 自分で登録した食品（製品名、1単位の量、kcal、PFC）
  - よく食べる組み合わせ（例：「いつもの朝食」）をまとめて入力
  - 【第2段階】AI 機能（下記）
- 量の選び方：g、または「1個」「1杯」「1袋」などの単位と個数

## 5. ヘルスケア連携（ショートカット）

- ショートカット「ヘルスケア送信」を配布する。中身は次のとおり
  - 今日の「アクティブエネルギー」「安静時エネルギー」の合計、最新の体重を取得（23:55 にも実行して、その日の最終値を送る）
  - サーバーの `/api/health` に POST する（専用トークン付き）
- 個人用オートメーションで1日数回（例：7時・12時・18時・22時）自動で実行する
- アプリを開いたときに「今すぐ同期」ボタンからも実行できる（ショートカット起動の URL を使う）
- 入力忘れの通知：同じショートカットがサーバーに未入力の食事を問い合わせ、あれば iOS の通知を出す
  （例：12時の実行時点で朝食が未入力なら「朝食が未入力です」）

## 6. AI 機能（第2段階・API キーを用意してから追加）

- 食事の写真からメニューと kcal・PFC を推定する
- 製品名で調べる（例：「スーパーカップ バニラ」）。Web 検索でメーカー公式の値を探し、確認してから自分の食品として登録する
- パッケージの栄養成分表示を撮影して読み取り、自分の食品として登録する
- API キーはサーバー側（Cloudflare の Secret）にだけ置く

## 7. 開発の進め方

1. 土台：PWA の画面、初期設定、D1 のテーブル、Cloudflare へのデプロイ
2. 食事登録：成分表の取り込み、自分の食品、履歴・お気に入り、組み合わせ
3. 今日のサマリー：枠の計算、ゲージ、借金、体重記録
4. ヘルスケア連携：`/api/health`、ショートカットの作成手順、入力忘れの通知
5. 通算記録：各種グラフ
6. AI 機能

## 8. その他の決定事項

- アプリの表示名：Foodiet
- 1日の区切り：0時（日本時間）
- 食べなかった食事は「食べなかった」として記録でき、入力忘れの通知の対象から外れる
